# WP10 — Next.js 16 + React 19 + Clerk (design)

**Date:** 2026-11-27  
**Status:** Draft for approval  
**Related:** [`DEPENDENCY_COMPATIBILITY_REPORT.md`](../../modernization/DEPENDENCY_COMPATIBILITY_REPORT.md) · [`MIGRATION_RISK_ASSESSMENT.md`](../../modernization/MIGRATION_RISK_ASSESSMENT.md)

## Goal

Move current **Next 14.2.35 / React 18 / Clerk 5.0.3** toward **Next 16 / React 19** with a compatible Clerk major, without rewriting product features.

## Recommended path

| Stage | What | Why |
|-------|------|-----|
| B (optional) | Next 15 + React 19 (+ Clerk bump as required) | Smaller jump; isolate breakages |
| C (target) | Next 16 + React 19 + Clerk current | Final target per roadmap |

**Default recommendation:** Branch-based **14 → 15 → 16** (or document direct 14 → 16 if you accept higher risk). Keep `middleware.ts` until Next 16 docs require proxy rename.

## In scope

- Bump `next`, `react`, `react-dom`, `eslint-config-next`, TypeScript if required
- Bump `@clerk/nextjs` to a version that supports the chosen Next major
- Fix compile/runtime breakages (App Router APIs, auth helpers)
- Update `TECH_STACK.md` + `AGENTS.md` “current” versions when green

## Out of scope

- WP11 tests/CI (can land after or in parallel later)
- WP12 Decimal money migration
- Feature work

## Risks

- Clerk API shifts (`auth()`, middleware protect)
- React 19 / types peer dependency noise
- Residual CVE path only clears on 15.5+/16

## Exit

- `npm run build` green on target stack
- Smoke: sign-in, wizard, create/delete transaction, manage
- Docs updated
- **No commits / no production deploy** unless you ask

## Approval needed

Confirm: **B then C** (safer) vs **direct to 16**, then implementation starts on a dedicated branch if you prefer isolation.
